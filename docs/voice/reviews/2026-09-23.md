## 0. The biggest weakness, stated first

**Every prose defect this seat has spent nine runs patching is sitting in the
material the generator is handed, and no run had ever looked at it.**

generator's own `gather()` against the live database, read-only, and read the

| In today's payload | What nine runs called it |

| 2 of 3 reading-list papers already covered in another section | ban list 15, the complete dump |

The model did not type those hyphens into "on-policy" and "inference-time".
It copied them. The claim text is machine-extracted from PDFs, where the
typesetter's hyphen is ordinary, and it reaches the writer unwashed.

`prompts/digest.md` now runs to about forty rules and every one of them is a
gate on the output. The file describes the payload in eight lines as a list
of field names and says nothing about its condition. There is exactly one
place where it admits the input is dirty, and it is the `dates` field, which
the writer is told to normalize from an en dash. That instance was never
generalized. The file holds the right instruction for one string out of
several hundred.

The instrument explains the six days. Reading finished text tells you a
defect exists. It cannot tell you whether the writer produced it or inherited
it, and those have opposite fixes. The first wants a sharper prohibition,
which is what got written, twice. The second wants a cleaning step where the
material comes in, which got written nowhere.
