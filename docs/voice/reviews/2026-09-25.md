## 1. What this run did instead: the second gate, turned on this seat

Incident 20 is the standing lesson of this repo, and L-A9 is the same
lesson as company law: recording a rule is not enforcing it. Every register
needs two gates, one that decides something gets written down and one that
decides something gets checked before it ships, and the org keeps building
the first and forgetting the second.

Last night's run wrote four patches into `prompts/digest.md` and appended
four new tells to `docs/voice/ban-list.md`. This run checked the mapping
between those two lists, which nothing had ever done, and it does not hold.

| Tell appended 2026-09-24 | Reached the generator? |
|---|---|
| 51. The rule's own name printed as a label | **No** |
| 52. The fix by deletion | Yes, patch 3, through canon law 13's gate |
| 53. The prohibition that supplies the string | Yes, patch 1, all four heading slots |
| 54. The term introduced under one name and used under another | **No** |

Two of the four were written down and left there, in the same pull request
that patched the other two, by the seat whose charter names this exact
failure mode. That is the finding of this run, and it is recorded as
`INC-2026-09-25-tell-recorded-never-enforced`.

It is worth being precise about how the gap happened, because the shape
generalizes past this file. A grade produces findings of two kinds at once,
and they leave through different doors. A finding about a *sentence* the
issue printed becomes a patch, because the patch is obvious and the prompt
has a place for it. A finding about a *class* becomes a ban-list entry,
because the entry is where a class of tell belongs. Entries 51 and 54 are
both class findings, and writing them felt like completing the work. The
ban list has never had anything that asks what happens next.

It does now. The header of `docs/voice/ban-list.md` carries a standing rule
in this PR: a new entry ends either in the change to `prompts/digest.md`
that enforces it or in the ledger entry saying why no prompt change can
reach it. Entries 51 and 54 now carry the first kind, added below.

## 2. The patches

Two changes to `prompts/digest.md`. Each is the smallest change that turns
a tell already in the register into a rule the generator reads, each names
the law it serves, and neither invents a finding this run did not have
evidence for.

**1. The first-use pass counts the term the reader meets.** Serves canon
law 12a and ban list 54. The pass looks for terms standing without a
clause, so a term that has a good clause under a different name passes it,
and the issue hands the outsider a definition for a word it does not use.
Row 18 defines "scaffolding" correctly, then uses that word twice and
"harness" thirty-eight times, beginning in its own title. The patch adds
the count that catches it and, per L-A14, the safe form beside the
prohibition: one name for one idea all the way through, or the join written
at the first appearance of the second name.

The worked example in the patch is deliberately about a night shift and not
about harnesses. Ban list 53 was written last night about exactly this: an
exemplar drawn from the material the generator will be handed stops being
an illustration of the answer and becomes the answer. Row 18 is a harness
issue, the next one may be too, and a specimen naming the payload's own
subject is the tell reproducing itself through the file that bans it.

**2. Rule names in this file are internal vocabulary.** Serves law 3 and
ban list 51, through the test entry 14 already states. The generator's
internal-vocabulary rule lists the codebase's words, which are claim ids,
support counts, triage scores, the ISO week code and "ingested". It has
never listed its own. Row 18 printed `**The number that matters:** 44.3%
with the harness gone, up from 23.3%`, which is the title of a formatting
rule in this file welded to the front of the sentence obeying it. Last
night's patch 4 rewrote that rule's example so the example could not ship.
It left the name, and the name is what shipped. The patch adds one class
sentence: obey a rule, never label the sentence with it, because a line
that announces what it is doing has handed the reader the recipe.

## 3. Structure watch: the pass that cannot prove it ran

Charter step 4, and this one is filed rather than patched.

The first-use pass has been written twice, in `be88232` and again in
`c3b4c49`, which strengthened it specifically to catch the owner's
nicknames. Both were live in `0f642e2ce9f3`. The issue that prompt wrote
carries nineteen terms of art standing bare, one of them a naked acronym,
and the pass itself says that more than about five is a sign the issue is
carrying too much. It did not fire.

A third rewrite is not the fix, and the reason is visible in the same
issue. The link rule and the evidence-grade rule sit two lines apart in
that prompt, the same model read both, links came in at five out of five
and grades at zero out of four. The difference is one sentence: "Count the
items. Count the links. They match, or the issue is not finished." Links
are countable in the finished text. A missing gloss is not. Nothing in the
output distinguishes an issue whose first-use pass ran from one whose did
not, so the only evidence the model has that it ran the pass is its own
recollection of having intended to, and that evidence always comes back
positive.

That is a property of where the check lives rather than of how it is
worded, so it is a pipeline item. It is in the ledger for the engineer with
the mechanical half spelled out, because one slice of it is decidable
without a language model: a bare acronym is a regular expression, ban list
26 already bans it outright, and `VLMs` shipped.
