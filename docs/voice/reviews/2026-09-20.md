## 1. The single biggest weakness

**The gates read `#` lines and bold runs, so the issue put its labels in
italics and walked through.**

2026-W37 prints this, twice:

> *Procedure*
> 1. Let a held-out verifier emit a pass/fail outcome for each assertion.

The heading gate at the end of prompts/digest.md is thorough. It reads
back every line beginning with `#`, it names the eight forbidden
strings, and since run 5 it reads back bold runs standing alone so that
"**Contradicted**" cannot sneak the same label one level down. It does
not read italics. "*Procedure*" is the same failure a third level down,
it sits over a list in every item that has steps, it would fit any item
in any issue, and it survived five rounds of grading by a seat that was
looking for the failure in the two typefaces it had already lost in.

The lesson generalizes past this one word. Every time this seat has
caught a label, it has patched the specific place the label was standing
and not the class. Heading level, then bold, now italic. The patch this
run makes says the general thing out loud: a label is a label in any
typeface, and the gate reads all of them.

## 7. Structure watch

**The masthead, second filing.** `MASTHEAD` in pipeline/weekly.py
injects a fixed italic line under every H1 after the model has finished
writing, so no prompt change can reach the second-most-read line in the
issue. It recites the method, it lists the framework's three slots in an
order the generator no longer uses, it says "weekly" about a product
that is going daily, and it would fit any issue on any day.

It was filed for the engineer on 2026-09-19 and is still `proposed`. The
facts changed today, so it is filed again rather than edited: PR #35
turns the constant into `MASTHEAD[kind]`, gives the daily a second
standing line, and adds three tests asserting that each kind gets its
masthead under the title. An unresolved editorial defect is about to
acquire a copy and a test suite.

There is a second reason to raise it now. The generator writes a
contents line inside its opening, added in run 4 from the prose
benchmark. With the masthead in place, a reader meets a fixed
description of the product and then a written list of the day's items,
two lines apart, doing overlapping jobs. The fix is to delete the
constant and let the finding land first.

**PR #35 and the parallel-generator risk.** The daily prompt in PR #35,
`prompts/daily.md`, was written before digest.md absorbed the daily
cadence. Main now opens with "alexandria ships a daily issue and a
Monday weekly, and this one prompt writes both". If #35 merges as it
stands, the org has two generators, and the second one does not carry
the outsider test, the density rule, the first-use pass, the heading
gate, or the two rejected specimens, every one of which landed in
digest.md after #35 was opened. That is the parallel structure canon law
9 exists to prevent, and it is a merge-order problem rather than a fault
in the engineer's work. Flagged here, and named in the pull request, for
the owner's merge decision.
