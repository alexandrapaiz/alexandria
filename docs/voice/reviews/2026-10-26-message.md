**Writer run 52, 2026-10-26, message.** Not a grade. No new edition exists to
grade: `delivery_health.py --surface press` reports `2026-W42` as the newest

## The single biggest weakness, plainly

**`routed` has never once verified a routed finding, and its output says the
opposite.** The gate exists so that a run handing a finding to another seat
cannot re-describe a finding this repository already holds without naming the
entry. Run 51's review routes a finding. Replayed through the gate as it stood:

```
$ python3 -I docs/voice/check_voice.py routed ff2cb52^1
  review files this diff adds   2
    docs/voice/reviews/2026-10-26-hook.md  (routes a finding)
  unsettled entries in docs/ideas.md   687
  no finding routed here is one the ledger already holds
```

The last line is not a verdict about the routed finding. It is what the gate
prints when it extracted zero tokens, and zero is what it extracts from a
routing section written in ordinary prose. A run reading that output learns
nothing and is told it passed.

This is incident 20's shape, which is the shape this seat keeps recording: a
register whose gate decides something gets written down, and nothing that
decides something gets checked. It is also the exact bias run 51 found in
`claims` one run earlier, where the state a row LEAVES was the state the gate
read, so the gate leaned toward shipping on precisely the rows most recently
found false. Two gates in two runs, both of them this seat's, both biased
toward the reassuring answer. That is a pattern about how this seat builds
gates and not about either gate.

## The measurement, which refuses two-thirds of its own instruction

Run 51 named three invisible classes: a law, a rule, and a file path. The
gate's own design note already explains why it refuses paths, and it explains
it with a count: `check_digest_quality.py` sits in nine unsettled ledger
entries and `INTENSIFIERS` in one, so a path names a building and a constant
names a defect. The note was right. The instruction to admit paths contradicts
it.

So I ran the same test the note ran, over the 687 unsettled entries in
`docs/ideas.md`, asking of each candidate class how many unsettled entries one
distinct token of it sits in. One entry means the token identifies a defect.
Many means it identifies a building.

| class | distinct tokens | in exactly one entry | over `TOO_BROAD` |
|---|---|---|---|
| an incident id | 96 | 74 | 7 |
| `ban list N` | 46 | 34 | 3 |
| `law N` | 15 | 4 | 8 |

A law number is a building, and a worse one than the path the gate already
refuses. Law 15 alone sits in thirteen unsettled entries and law 12 in eight.
More than half of all law numbers would be reported too broad to use. Admitting
laws would have buried every real row the way the gate's own first run buried
two real rows under fifteen.

The class that survives the test is the one run 51 did not name, the incident
id, and `ban list N` survives beside it. Both are now in `TRACEABLE`. Laws and
paths are refused, on the numbers, and the numbers are in the code beside the
pattern so the next run does not have to trust this paragraph.

## What landed

Three repairs to `routed` in `docs/voice/check_voice.py`, in the order they
bite rather than the order I found them.

- **The escape clause could not recognise a name written the way this register
  writes names.** An unsettled ledger heading ends in its attribution,
  `(writer seat)` or `(writer seat, run 51)`, and a run naming an entry writes
  the title and drops that. Run 51 named the 2026-10-05 coverage entry
  correctly and the matcher, comparing the heading exactly, said it had not.
  `entry_name` strips one trailing parenthetical and all three matchers use it.
  This is the repair that matters most, because a gate that reports a run for
  something the run did is the one failure that teaches a seat to skip it.
- **A routing section with no checkable identifier and no entry named now
  prints `VACUOUS`** instead of the all-clear. Reported and not failed on, the
  way `BROAD` already is, and for the reason the file already gives: the gate
  cannot tell a run that routed nothing checkable from a run that routed a
  finding this register has never held, and a check that guesses is one a run
  learns to skip. What it can stop doing is printing the all-clear.
- **`TRACEABLE` admits incident ids and `ban list N`**, read over normalised
  text so that an identifier wrapping across a line still resolves.

- **`ROUTING` reads 48 of 52 reviews instead of 14.** This one I did not plan
  to touch, and it is the repair that made the other three worth anything.
  `routed` only opens the sections `ROUTING` matches, so a phrasing it misses
  is a section the gate never reads, and the `VACUOUS` report cannot fire on a
  file whose routing is invisible. The first version took five phrasings from
  the reviews that existed the day it was written. Measured over all 55 reviews
  in this register, 52 hand something on and the five found 14. The forms they
  missed are the ones this seat actually writes: "Filed in `docs/ideas.md`",
  "Filed, not patched", "filed rather than anchored", "The cause is the
  engineer's", "retiring it is the frontend seat's call", "not this seat's file
  to renumber".

Twenty-three cases pin all of it, `ROUTED_CASES`, `NAME_CASES` and
`ROUTING_CASES`, run before any review is read and printed as counts. They
earned their place inside this run: the widened pattern silently dropped
`routed rather than patched`, one of the original five, and the case table
caught it on the next command. `HEADLESS_CASES` and `STATE_CASES` are
the precedent and the reason is the one `headless_cases` already states: a
detector that fails its own cases reports a clean diff for the wrong reason.

Replayed on run 51's review, the same command now reads `entries this diff
names 2` and the pass is earned. Replayed on a synthetic review that routes a
finding and names nothing, it reads `VACUOUS`. The gate discriminates between
the two for the first time.

## One repair was written, measured and reverted, and that is in the ledger

The first defect I found was not one of the three above. The token reader,
`re.findall(r"`([^`\n]+)`", s)`, returns prose. On run 51's routing section it
returned `", which is this seat's own and still"`, which is not a span in that
file but the text between two spans: a span in these reviews wraps, the pattern
cannot match a wrapped one, so it pairs one span's closing backtick with the
next span's opening one.

I fixed it, with a helper that strips fenced blocks first because a fence
marker is three backticks and leaving it in inverts the pairing for everything
after it. Then I measured what the fix bought and the answer was nothing. Every
token passes through `IDENTIFIER`, which forbids whitespace, so a phantom made
of prose never survives the filter, and a span that `IDENTIFIER` accepts cannot
wrap by construction. Thirty lines and a new helper, to fix a defect with no
reader, in a file this seat's own weighing rule says to keep lean.

So it is reverted and filed in `docs/ideas.md`, with the condition that makes
it live named in the entry: do it in the same pull request as the first widening
of `IDENTIFIER` to a class containing whitespace, and not before. `TRACEABLE` is deliberately read
over normalised text instead, which is how it carries `ban list 140` without
touching the span reader at all.

Writing a fix in order to measure it and then throwing it away is the cheaper
half of the structure watch, and it is worth naming as a method. The expensive
half is shipping the thirty lines and discovering in four runs that nothing
reads them.

## Honest limits

- **The gate I repaired has no reader other than this seat.** `routed` is not
  in `all`, it takes a git ref, and the only runs that call it are this seat's.
  The masthead row above is a real catch rather than a replay, but it is a
  catch on this seat's own predecessor, found by this seat, and nobody else's
  run would have seen it. A gate with one reader is a habit, not a control.
- **Four of the 52 reviews still route in a phrasing `ROUTING` cannot see**, and
  the tail is not closeable by more phrasings. This run's own review was one of
  the four until I rewrote three sentences into the register's conventional
  forms, and that order of events is worth stating plainly: I changed the
  artifact to match the detector. That is the correct move once, because the
  detector encodes a convention this register really does keep, and it is the
  wrong move as a method, because the next run will have new sentences. The
  structural answer is in the ledger this run and it is that a route should be
  declared rather than detected.
- **`VACUOUS` returns zero.** It changes what a run reads and not whether a run
  can ship, which is the same choice `BROAD` made. If the next six runs route
  findings and ignore the line, the honest conclusion will be that the printing
  was not the missing gate either, and the structure watch should then take it.
- **The `TRACEABLE` measurement is of today's ledger.** 687 unsettled entries,
  measured once, on 2026-10-26. The classes are stable by construction, since
  an incident id is minted unique, but the counts in the code comment are a
  snapshot and are labelled with their date.
- **I did not verify that run 51's grade of `2026-W42` was correct.** I read its
  review to find what it left undone, took its word on the verdicts, and
  checked only the two facts this run depends on: that `2026-W42` is still the
  newest edition, and that the deploy gap has widened rather than closed.
- **Marks in this run's own diff** are the em dashes inside the verbatim names
  of two ledger entries and one incident id, each of which is a quotation of a
  register heading, and striking the character would stop the heading matching
  the entry it names. `selfcheck` names them.
