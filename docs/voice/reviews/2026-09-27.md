## 4. The masthead was fixed, and no reader will ever see the fix

Run 14 corrected `MASTHEAD` in `pipeline/weekly.py`. The false claim is gone
from the constant:

```
-    "*The latest in AI research, read in full and distilled weekly: ..."
+    "*What's new in AI research, what's gaining acceptance, and what newer "
+    "evidence has overturned.*"
```

The published issue still says this, and it is the second line a visitor
reads:

```
*The latest in AI research, read in full and distilled weekly: what's new,
what's gaining acceptance, and what newer evidence has overturned.*
```

**Why the fix does not reach it.** `add_masthead` in the same file splices
the constant into the body before the body is stored:

```python
def add_masthead(body: str) -> str:
    lines = body.split("\n")
    if lines and lines[0].startswith("#"):
        return "\n".join([lines[0], "", MASTHEAD, ""] + lines[1:])
```

So the string is baked into the artifact at write time rather than composed
at read time. `site/lib/content.js` renders the stored body whole, from the
markdown fixture locally and from Neon in production, with the same
interface either way. Changing the constant changes what the next issue will
carry and cannot change any issue that already exists. Every stored body
keeps the sentence it was printed with, permanently.

Today that means one page, because 2026-W37 is hidden and 2026-W39 is the
only published issue. It is the whole public archive.

**Why this is worth a finding rather than a note.** Law 15 says the claim
about alexandria's own reading is the one sentence in an issue a reader
cannot check against a linked paper, so they either trust it or stop
trusting the issue. The corrected constant is the fix for the sentence.
Nothing was the fix for the surface. This is the third time law 15 has been
repaired on one surface while a live one kept the claim, after the print's
close and the home page, so it goes in the incident register.

The repair is not this seat's to make. The stored body is the pipeline's and
the page is the frontend seat's, and altering an issue that has already been
sent is the owner's call. Filed in the ledger with both options stated.
