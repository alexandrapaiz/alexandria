Run 6 named this correctly, in its own words: five rounds "patched the
place the label was standing rather than the class." It then patched the
typeface, which is also the place. The gate it shipped still opened with

The org already owns the right test and has written it down twice. Ban

engineer's new standard, `docs/standards/digest-quality.md`, states it
almost word for word and then files it under what only a person can
check, after publication. Between the rule and the artifact, nothing
asked the question.

**The patch.** The pre-output gate now collects every line that announces
a block instead of saying something, at any level and in any typeface,
and puts one question to each: could this exact line sit over a different
day's items without changing a word? The thirteen known labels stay in
the file as examples, with a sentence saying why they are not the test:
"a line that passes only because it failed to match a string has not been
checked at all."

## 4. The second finding: the four sections are fixed, the news is not

Found by reading the generator against canon law 11 rather than against
the issue, and it has never been graded before because the only issue we
have is a heavy week where all four slots had material.

`prompts/digest.md` said "Never reorder them and never add a fifth" and
said nothing anywhere about a slot with nothing in it. What it did say,
in the fell-behind section, was **"If a kind is empty, say so in one
line, because that is itself information."** That is an instruction to
print an absence, and it sat in the same file as run 6's new rule that
"An empty stream is never news" and the standing rule that an empty
stream is "pipeline information for the ledger and not reader-facing
copy". Three rules, one subject, two answers.

On a heavy week that contradiction costs nothing. On the daily cadence it
governs most days, because most days overturn nothing. The issue it
produces is a freshly written heading, correct by every rule in section 3
above, standing over one sentence explaining that there is nothing
underneath it. The reader scrolls to learn that nothing happened.

That is ban list 21's fixed-length issue measured in sections instead of
words, and it is new enough to be its own tell. **Ban list 35**, the
section kept for the shape.

Three edits: the length rule now says a slot the day gave nothing to
prints no heading either and names the daily as where this will be
ordinary; the fixed-order rule now binds the sections that appear rather
than demanding four; and the fell-behind line stops mandating an absence
and matches the other two rules.

## 6. The laws, one verdict each, against 2026-W37

Retained in short form for the record. Nothing here is new; the evidence
is in run 6's review and in ban list 13 through 34.

1. Plain sentences, no em dashes, no semicolon joins. **Fail.** "a
   **dense verification reward**—counting how many assertions an answer
   gets right—produces".
2. No buzzwords, every line actionable. **Pass, narrowly.** No slop
   lexicon. The advice lines are real.
3. Sell the product, never the recipe. **Fail.** The masthead, "read in
   full and distilled weekly", and the footer, "310 claims distilled,
   102 edges drawn", are both recipe. The first is injected by
   `pipeline/weekly.py` and no prompt change can reach it (ledger, twice).
4. The headline is a finding. **Fail.** "Richer feedback boosts
   long-horizon agents [September 7-13, 2026]" names a direction and
   carries the date the owner rescinded.
5. Relevance is impact. **Partial.** Traction exists but is ranked by
   raw support count, ten bullets tied at "(3 supports)" and "(2
   supports)", which is the count deciding and not the judgment.
6. Evidence grades in-line. **Fail.** Not one item grades its evidence.
7. Honesty serves items, never the method. **Fail.** "No citation movers
   were recorded this week."
8. Links reach the full text. **Fail**, twice over. The three source
   lines that exist all read `[link](https://arxiv.org/abs/...)`: the
   abstract page rather than the full text, under link text that is the
   word "link". The nine reading-list entries carry no link at all, which
   the generator now calls the section's whole failure rather than a
   small one.
9. Her fine-tuning is the base layer. **Pass**, and this is the one the
   issue got right: the opening situates the reader in long-horizon RL
   and its sparse-reward problem before naming anything.
10. The dual-audience close. **Fail.** Absent. The issue ends on a count
    of edges.
11. Length follows the news. **Fail.** Ten identical traction bullets and
    nine reading-list entries, printed whole. Two of the three lead items
    rest on the same paper, T1, without saying so (ban list 16).
12a. Outsider test and density. **Fail**, hardest of all. Eighteen terms
    of art land bare. "Token-In-Token-Out", "Rollout-Routing-Replay",
    "PPO", "critic", "actor", "entropy", "MoE", "KV-cache eviction",
    "RLVR", "on-policy distillation", none introduced.
12. Framework names never print. **Fail.** All four printed verbatim,
    plus "**Contradicted**", "**Replaced**", and "*Procedure*" twice.

Eleven fails, two passes, one partial. The generator as it stands after

## 7. Custody note: the engineer's quality gate is not a parallel structure

My charter says no other seat writes newsletter structure or prose rules
anywhere else, so I read PR #60's `docs/standards/digest-quality.md` and
`tools/check_digest_quality.py` expecting to object. I do not.

That standard sources every rule it enforces to this seat's registers,
says so explicitly, and assigns the division correctly: "The writer seat
appends new tells, the owner rules, the engineer keeps the machine half
in step with the list." It is an enforcement layer for my rules, not a
second set of them, and it is the gate the register map says the org
keeps forgetting to build. It should merge.

Two notes for the owner's merge order, neither a fault in that work.

**The enumeration shape is in the code too.** `skeleton-heading` blocks
on the known slot labels, which is section 3's defect rendered in Python.
It should stay exactly as it is and gain a companion, filed in the ledger
this run: compare today's headings against the previous issues' headings
out of the `digests` table and block on a repeat. "Would fit tomorrow's
issue" is a judgment a regex cannot make, but "fitted yesterday's" is a
set comparison, and it catches labels nobody has invented yet.

**`prompts/daily.md` is still a second generator.** Run 6 flagged this
against PR #35 and #60 now carries the same 133-line file. It was written
before `digest.md` absorbed the daily cadence, and it carries none of the
outsider test, the density rule, the first-use pass, the heading gate, or
this run's two fixes. If it merges as it stands, the org has two
generators and the newer one is the weaker, which is the parallel
structure canon law 9 exists to prevent. This is a merge-order call for
the owner, not an objection to the engineer's work.
