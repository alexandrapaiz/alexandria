## 0. The finding that governs the rest

**A fix is already in flight for why arXiv never gets read. Nothing is in
flight for why the feeds never produce claims — and the feeds are where
agent identity lives.**

Triage has routed 1,694 papers all time. Split by tier:

|---|---|---|---|---|

Tier `a`/`a-low` reading zero is the inversion PR #44 fixes. The new fact

every single one was routed `index`. Not one has ever become a claim.**

That is not a backlog. Those papers were read and decided. `index` means
"keep it searchable, spend no more on it" — and `index` produces no claim,
so it is invisible to `semantic_search`, which only searches claims. The
agent-facing product cannot see any of it.

This is partly correct by charter: the research charter's own rule says
news, RSS and releases are **attention signals** that "never become
claims, because a headline is not evidence." `gh-*` release notes going to
`index` is the system working as designed.

But it collides with incident 21. Agent identity and portability knowledge
lives in exactly the places the charter classifies as signal — standards
repos, protocol specs, vendor changelogs. So the corpus is **structurally
incapable** of answering epitome's question through feeds, no matter how
many identity feeds are added. Incident 21's same-day remediation (A2A,
SPIFFE, MCP feeds, all tier `d`) cannot work, and will not work after #44
merges either, because #44 fixes the arXiv ordering, not the tier `c`/`d`
`index` ceiling.

**This is a real tension in the charter, not a bug in the pipeline**, and
it needs the owner's call — see §5. The charter simultaneously says feeds
are never claims *and* says "industry artifacts (framework releases,
identity standards, infra pricing changes) qualify alongside papers when
they carry real technical substance." Both cannot hold for a SPIFFE spec.

## 1. Digest verdict — 2026-W37

The only digest ever published (2026-09-14, the `digests` table holds one
row). Verdict: **the evidence trail is real and the arithmetic is honest,
but three of its sections misrepresent what the graph actually says, and
two sentences are fabrications.** Detail below, each with the query that
shows it.

### 1.1 Two factual errors in the published text

**A fabricated comparison.** The digest's opening says T1 "resolves 64 % of
tasks on Terminal‑Bench 2.1, **surpassing GPT‑3.5‑Turbo** and approaching
Claude Opus." The claim it rests on (C204) says T1 outperforms **GPT‑5.4
(54.8 %) and DeepSeek‑V4‑Flash (56.9 %)**. GPT‑3.5‑Turbo appears nowhere
in the corpus record, and neither does Claude Opus in this context. The
writer model downgraded a frontier-beating result into a trivial one and
invented the Claude comparison. This is the digest's lead item.

**A false attribution.** The digest says "researchers at **the same group**
released a 122 B Mixture‑of‑Experts terminal agent (T1)", tying T1 to the
FEE paper introduced one sentence earlier. They are different teams:
FEE (`arxiv:2609.08404`) is Hongbang Yuan, Zhuoran Jin, Yixin Cao; T1
(`arxiv:2609.11042`) is Junyao Yang, Yucheng Shi, Zhongzhi Li, Ruhan Wang.
No overlap. The digest invented a research-group relationship.

Both errors are generation-layer, not graph-layer: the claims are correct
and the digest departed from them. That points at `prompts/digest.md`, and
at the writer seat's factual-audit work already open in PR #40.

### 1.3 "Left behind" is wrong in full

Every deprecation flows from a `contradicts` edge at confidence ≥ 0.7
(`prompts/interpret.md`). The corpus holds **five** `contradicts` edges and
**five** deprecated claims — a 1:1 mapping. I read all five. **All five are
misclassifications.** Two failure modes:

**Same-paper "contradictions" (2 of 5).** A paper cannot contradict itself;
these are co-reported results.
- C12 → C11 (conf 0.88), both from *τ^τ-Bench*: "an expert-authored
  reference implementation achieves 82.2 %" vs "Claude Opus 5 under Claude
  Code passes only 23.9 %". That is a **human ceiling next to a model
  score in the same table** — the paper's central framing. The digest
  rendered it as "an earlier benchmark suggested Claude Opus 5 could solve
  only 23.9 %… a reference implementation now reaches 82.2 %, showing the
  earlier ceiling was far too low." Nothing was superseded; one paper's
  two numbers were staged as a refutation across time.
- C190 → C188 (conf 0.77), both from *Show-Harness*: "a semantic interface
  alone removes the need for embodiment-specific pretraining" vs "small
  VLMs can be adapted with a few GPU-hours of fine-tuning." Complementary.

**Cross-paper conflation via anaphora (3 of 5).** Claim text carries
relative references that the interpreter resolved across paper boundaries.
- C85 → C12 (conf 0.78): C85 (*EmbodiedSkills*) says "the same execution
  approach attains only 12.5 % on four memory-dependent **RMBench** tasks";
  C12 (*τ^τ-Bench*) says 82.2 % "on **the same benchmark**." Two different
  papers, two different benchmarks, two different systems — matched on the
  phrase "the same benchmark". The digest then told readers "the same
  reference implementation that achieved 82.2 % was later shown to drop to
  12.5 %," which is a statement about a system that does not exist.
- C82 → C5 (conf 0.78): robotics VLA skill interfaces vs search-agent ReAct
  rollouts. Different domains; not mutually exclusive.
- C136 → C129 (conf 0.90, the highest-confidence edge in the corpus):
  training-time *environment feedback* (FEE) vs prompt-time *environment
  information* (RealSWE). A keyword collision on "environment".

So the published "Left behind" section — the one thing that most
distinguishes this digest from TLDR AI — is **0 for 5**.

The concrete instance: both "Replaced" bullets are `refines` edges (0.78,

## 5. Meta-review — one proposal: `prompts/interpret.md`

**Evidence:** 5 of 5 `contradicts` edges in the corpus are wrong, and all 5
deprecations descend from them (§1.3). A 100 % failure rate on the relation
that feeds the digest's most distinctive section is a pattern, not an
anecdote. Two mechanical failure modes, both preventable in the prompt:

1. **Same-paper contradictions (C12→C11, C190→C188).** A paper's two
   co-reported results are not a conflict. Mechanically detectable.
2. **Cross-paper anaphora (C85→C12 is the clearest).** "The same
   benchmark", "the same approach" resolved across paper boundaries,
   inventing a shared referent.

Plus a third the same evidence exposes: the prompt defines `refines` but
nothing warns that downstream it is rendered as *superseded* (§1.4), which
is why a speculative-decoding claim was printed as replacing a layer-dropout
claim.

### 5.1 Why 75 % of edges are intra-paper — the mechanical cause

Found while drafting the diff, and it changes what the diff could honestly
claim. `pipeline/interpret.py:78-85` selects candidates with only
`where id < %s and embedding is not null ... order by embedding <=> %s`.
There is **no paper-boundary filter**, and the prompt is built from
`[id] claim_text` alone (`interpret.py:88-90`) — **the model is never told
which paper any claim came from, including the new one.**

A paper's own claims are distilled in one batch from one text, so they are
each other's nearest neighbours almost by construction. The shortlist is
therefore dominated by the new claim's own paper, which is precisely the
75 % intra-paper edge rate in §1.5. It is a retrieval artefact, not a
judgment failure.

This forced a correction to my own proposal. My first draft of the diff
told the model "when the candidate comes from the same paper, never say
`contradicts`" — **an instruction it cannot follow, because it has no
paper identity to check.** It would have shipped as an inert rule that
looked like a fix. The rule now asks the model to *infer* co-reporting
from shared system names, shared benchmarks and results-table shape, which
it can actually do from the text it receives.

**The real fix is one line of SQL and belongs to the engineer**, not to
this seat's whitelist: add `and paper_id <> (select paper_id from claims
where id = %s)` to the neighbour query. That deletes the failure class
rather than asking a model to reason around it, it mirrors the
`old.paper_id != new.paper_id` guard already living in `weekly.py`'s
`superseded` query, and it makes every shortlist cheaper by spending the
`NEIGHBORS` budget on other papers. Filed in the ledger.

**This is the run's one system diff** (charter: at most one per week).

## Appendix A — queries

All read-only, run against `NEON_RO_URL` on 2026-09-19.

```sql
-- §0 tier routing: the index ceiling
select p.tier, t.decision, count(*) from triage_log t
join papers p on p.id = t.paper_id group by 1,2 order by 1,3 desc;

-- §0 every claim's origin
select p.tier, p.source, count(distinct p.id) papers, count(c.id) claims
from claims c join papers p on p.id = c.paper_id group by 1,2;

-- §1.2 self-support vs external, as of the digest timestamp
select c.id, count(*) supports,
  sum(case when cf.paper_id = c.paper_id then 1 else 0 end) self,
  count(*) - sum(case when cf.paper_id = c.paper_id then 1 else 0 end) external
from claims c
join claim_links l on l.to_claim = c.id and l.relation = 'supports'
 and l.created_at < '2026-09-14 15:00:21+00'
join claims cf on cf.id = l.from_claim
group by c.id having count(*) >= 2 order by count(*) desc;

-- §1.3 every contradicts edge, with both papers
select l.from_claim, l.to_claim, l.confidence, cf.claim, pf.title, ct.claim, pt.title
from claim_links l
join claims cf on cf.id = l.from_claim join papers pf on pf.id = cf.paper_id
join claims ct on ct.id = l.to_claim   join papers pt on pt.id = ct.paper_id
where l.relation = 'contradicts';

-- §1.5 intra-paper edge share
select l.relation,
  sum(case when cf.paper_id = ct.paper_id then 1 else 0 end) same_paper,
  sum(case when cf.paper_id <> ct.paper_id then 1 else 0 end) cross_paper
from claim_links l join claims cf on cf.id = l.from_claim
join claims ct on ct.id = l.to_claim group by 1;

-- §1.5 unembedded claims
select count(*) filter (where embedding is null), count(*),
       min(created_at) filter (where embedding is null) from claims;

-- §1.5 arXiv version twins
select count(*) from (select regexp_replace(id,'v[0-9]+$','') b
  from papers where id like 'arxiv:%' group by 1 having count(*)>1) x;

-- §3 per-source ingestion, all time
select source, tier, count(*), min(fetched_at)::date, max(fetched_at)::date
from papers group by 1,2 order by 3 desc;

-- §4 citation velocity: zero papers have a second check
with checks as (select paper_id, citations, checked_at,
  row_number() over (partition by paper_id order by checked_at desc) rn
  from citation_log)
select count(*) from checks latest
join checks prev on prev.paper_id = latest.paper_id and prev.rn = 2
where latest.rn = 1;

-- §4.4 off-vocabulary topics
select t, count(*) from claims c, unnest(c.topics) t
where t not in ('skills','context-engineering','harness-engineering',
 'loop-engineering','memory','retrieval','multi-agent','evals',
 'post-training','serving','systems','tooling','other')
group by 1 order by 2 desc;
```
