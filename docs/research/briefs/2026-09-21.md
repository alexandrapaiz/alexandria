## 2. Extraction targets for Tuesday

**First choice: claims 386-390, *Emergence World: Adversarial
Stress-Testing of Long-Horizon Multi-Agent Systems*** (arxiv:2609.17320,
2026-09-15). Five claims, every one carrying a procedure:

- 386 — no evaluated world reached full resilience across all three
  stress events.
- 387 — recognising an attack does not produce restraint or recovery.
- 388 — model-level alignment is not compositional; the same model
  behaves differently in mixed versus homogeneous agent populations.
- 389 — persistent operation surfaces tool errors, goal drift, language
  opacity, and coordinated refusal of assigned work.
- 390 — five Agent World Indicators as system-level metrics for
  long-horizon autonomous runs.

This is the closest thing the corpus holds to the containment priority.
389's coordinated refusal is multi-agent collusion observed rather than
theorised, and 390 is containment evaluation, which is the sub-area the
charter defines as knowing how you test that an agent cannot reach what
it must not. 388 is the claim a builder would act on tomorrow: a model
validated alone tells you little about the same model in a mixed
population.

One caveat the skill agent must carry into the draft. These five claims
have **zero edges** in the claim graph — no supports, no refines,
nothing. They are a single paper's word. That is a thin evidence base
for a skill, and the honest options are to draft it with the single
source named plainly, or to wait for corroboration that the ingest gap
in section 4 may now start supplying.

**Second choice: the harness-over-architecture cluster around claim 4.**
Three independent papers agreeing is the best-corroborated position in
the corpus, and it is directly actionable: constrain the tool set, cap
the context, use a fixed judge. Weaker as a *new* skill, because
`self-improving-post-training-loops` already stands in gold nearby, so
check for overlap before drafting.

**Do not draft from claims 73, 43, or 45.** They look like traction in
the issue and are not; see section 3.

## 3. What the engineer should know

Four of these are corpus-integrity failures, and each disables something
another seat is being asked to use.

**The interpret prompt in production is three days stale, and every edge
in the graph proves it.** All 206 edges, including the nine written
today, carry method sha `fbe080261d6b`. `prompts/interpret.md` at HEAD
hashes to `6706ec7bffee`. The gap is commit a94a003 of 2026-09-19, a
previous meta-review that sharpened exactly the rules being broken. The
prompt is baked into the Modal image by `add_local_file`, so a merge
changes nothing until someone runs `modal deploy`. This applies equally
to `distill.md`, `triage.md`, `digest.md` and `sources.yaml` — every
file ADR-12 lets this seat touch. Incident 23, filed this run.

**All five `contradicts` edges are miscategorised, and three reached
subscribers.** Two are intra-paper, where one results table's baseline
and headline were read as a conflict. One is a cross-paper anaphora
failure that produced a false sentence in the published issue: *"The
same reference implementation that achieved 82.2% was later shown to
drop to 12.5% on memory-intensive tasks"* joins two different systems on
two different benchmarks that have no relationship. The highest-confidence
edge in the set, 0.90, links a reinforcement-learning environment result
to a prompt-content ablation on the strength of the shared word
"environment". `interpret.md` at HEAD forbids all five by name and
carries one of them as its worked example, which is the point of the
paragraph above.

**"Gaining traction" counts a paper citing itself.** Twelve of the 25
claims that qualify are supported only by their own paper. The issue
printed "(3 supports)" against *Compile-by-training*, whose three
supporters are all itself, and "(3 supports)" against Iris, which four
independent papers back. Same label, different things. The fix is a
`count(distinct paper_id)` where the query currently counts rows, and it
belongs in whatever produces that section before the next send. Note
this also passes O1 KR3 as written: those items do carry a claim-graph
edge, so the monthly audit cannot catch it.

**Embeddings stopped.** 225 claims since 2026-09-17 and 4494 papers
since 2026-09-10 have none. `distill.py` calls that sweep self-healing
and it has not healed in eleven days while claims kept landing daily, so
distill runs and the sweep inside it does not finish. This disables
`semantic_search` over everything newer than 2026-09-16 and returns the
embedding-novelty signal to NULL. The security seat's register names the
one plausible neighbourhood: `Qwen/Qwen3-Embedding-0.6B` is the only
upstream we pull at an unpinned revision.

Two smaller ones. 137 papers exist twice, once with an arXiv `v1`
suffix and once without, 120 of those pairs disagreeing on tier — cost
is 110 wasted triage calls and an inflated footer count, and no graph
damage, because no pair has both rows distilled. And the claim graph
reaches back 30 days: 3706 papers older than that, down to 2015, have
produced zero claims between them, so the relevance law's own example of
a 2023 paper compounding through the field is not something this system
