### The whitelist holds two classes of file

ADR-12 authorises this seat to propose diffs to `prompts/*.md` and
`sources.yaml`. Those paths reach production two different ways:

- **Baked into a Modal image** and frozen until someone runs `modal
  deploy`: `digest.md`, `distill.md`, `interpret.md`, `triage.md`,
  `rag-answer.md`, `skill-extract.md`, `sources.yaml`. Each is installed
  with `add_local_file` (ingest.py:23, distill.py:53, interpret.py:27,

  every `prompts/*-agent.md` seat charter, which its GitHub Actions
  workflow loads by telling the agent to read the file
  (`.github/workflows/agent-*.yml`).

Nothing in the charter, in ADR-12, or in the repo says these differ.

## D. All five `contradicts` edges are miscategorised

```sql
select l.from_claim, l.to_claim, l.created_at::date, cf.paper_id, ct.paper_id
from claim_links l
join claims cf on cf.id=l.from_claim join claims ct on ct.id=l.to_claim
where l.relation='contradicts' order by l.created_at;
```

| edge | written | error |
|---|---|---|
| 12 -> 11 | 2026-09-08 | Same paper. An 82.2% expert reference and 23.9% for Claude Opus 5 are two systems measured on one benchmark: a comparison. |
| 82 -> 5 | 2026-09-11 | Different domains. EmbodiedSkills is robotics, Iris is search. The claims never meet. |
| 85 -> 12 | 2026-09-11 | Different systems on different benchmarks (RMBench, tau^tau-bench). This edge produced a false sentence in 2026-W37. |
| 136 -> 129 | 2026-09-15 | Feedback-enriched environments against which prompt fields help coding agents. Unrelated. |
| 190 -> 188 | 2026-09-19 | Same paper. Two complementary findings from Show-Harness; `refines` at most. |

Two of the five were written after the corrected prompt merged, by the
stale prompt that is still running.

Two of the five join claims that share a `paper_id`. A paper does not
contradict itself, and that is checkable without a model:

```sql
select l.relation,
       count(*) filter (where cf.paper_id=ct.paper_id) as same_paper,
       count(*) as total
from claim_links l
join claims cf on cf.id=l.from_claim join claims ct on ct.id=l.to_claim
group by 1;
-- supports    | 77 | 119
-- refines     | 80 | 100
-- contradicts |  2 |   5
-- duplicates  |  1 |   1
```

## E. Both traction instruments are down

```sql
select count(distinct paper_id), min(checked_at)::date, max(checked_at)::date
from citation_log;
-- 166 | 2026-09-09 | 2026-09-21
```

166 papers of 7,991 are citation-tracked, and the last check was three
days ago. The fastest mover in the corpus is 0.14 citations a day.

`discovery_report`'s `citation_velocity_outliers` cannot return a row.
It filters `p.tier not in ('b','c')`, and:

```sql
select p.tier, count(distinct p.id) from citation_log cl
join papers p on p.id=cl.paper_id group by 1;
-- b | 166
```

Every tracked paper is tier `b`, which the query excludes. It is empty by
construction, not because the week was quiet.

`rising_authors` and `rising_institutions` filter on first-seen inside a
21-day window, and the corpus itself is 19 days old, so the window is the
whole corpus. It returns Peking University, Stanford, NVIDIA. The
source-discovery document predicted this exactly and put the signal's
usefulness at 60-90 days of history.

## G. Incident 24: the 2026-09-21 cron did fire

Incident 24 records it as unresolved, "the schedule either never fired or
died before logging; to be confirmed on the Modal dashboard's schedule
history, which the CLI does not expose." The database answers it without
the dashboard:

```sql
select date_trunc('minute', checked_at), count(*) from citation_log group by 1 order by 1;
-- 2026-09-09 02:56:00+00 |  12
-- 2026-09-11 18:21:00+00 |  31
-- 2026-09-14 15:00:00+00 |  25
-- 2026-09-20 05:54:00+00 | 104
-- 2026-09-21 15:00:00+00 |  62
```

15:00:00 UTC on 2026-09-21 is the Modal Monday cron slot exactly, and it
matches the 15:00:00 stamp of the 2026-09-14 run that did publish. The
run fired, reached Neon, and wrote 62 rows. `weekly()` calls
`check_citations` first, inside its own try/except, and only then calls
`write_digest` (weekly.py:517-527), so the run died after the citation
loop, at the model call. One cause, not two.
