# Market brief — 2026-09-18

First run of the market research agent (ADR-17). Full landscape and
positioning built this run; see docs/market/landscape.md,
docs/market/positioning.md, and docs/market/opportunities-2026-09-18.md
(the owner's directed opportunities report) for the complete detail behind
this page.

## Findings that matter

1. **The Claude skills ecosystem has a documented quality crisis.** A Show
   HN "State of Skills" report (216 public Claude Code skills audited)
   found 69% won't reliably trigger, and 57% of subagents declare no
   tools list, an unintended permission-escalation risk.
   [news.ycombinator.com/item?id=49744398](https://news.ycombinator.com/item?id=49744398),
   2026-09-17. **So what:** this is quantified, dated evidence that
   verification is the open lane in skills, not more distribution.
   Alexandria's claim-graph-backed skill library is a direct answer to a
   named, measured problem, not a hypothetical one.

2. **HN is skeptical of paying for skill content, but concedes curation
   is the defensible value.** On a Show HN for skillbay.sh, a hand-curated
   skill marketplace, the top comment asked why anyone would buy a
   markdown file an LLM could generate for free; the founder conceded
   AI-generated skills "are usually pretty bad" and that's why he
   hand-curates.
   [news.ycombinator.com/item?id=49743459](https://news.ycombinator.com/item?id=49743459),
   2026-09-17. **So what:** the sales pitch must always sell the
   evidence and verification layer, never a bare skill file, or the
   $20/month price will look wrong against the $5-a-skill anchor HN
   volunteered.

3. **The $20/month paid spine prices in the right neighborhood.**
   Single-author technical newsletters cluster at $15/month (The
   Pragmatic Engineer, Stratechery Plus). Actual research tools price
   higher: Consensus Pro ~$20/month, Elicit Pro $49/month. Alexandria's
   tier sits at the boundary between the two clusters, correct since it
   sells tooling, not more reading.
   [newsletter.pragmaticengineer.com/about](https://newsletter.pragmaticengineer.com/about),
   [elicit.com/pricing](https://elicit.com/pricing). **So what:** no
   pricing change is indicated by this week's evidence; annual anchoring
   at $200 (ten months) is plausible but unproven, worth a two-question
   test rather than a launch-day commitment.

4. **No independent benchmark exists for multi-agent orchestration
   patterns**, and practitioners are asking for exactly that. An Ask HN
   thread on production multi-agent systems: "I've not really seen
   anything outstanding in this space" on observability tooling.
   [news.ycombinator.com/item?id=49689454](https://news.ycombinator.com/item?id=49689454),
   2026-09-13. **So what:** a maintained orchestration-pattern benchmark,
   tied to the claim graph, is a concrete, novel feature candidate (see
   opportunities report).

5. **Skill libraries bloat context across unrelated tasks, a live
   operational pain.** Show HN "Skillzero" addresses exactly this; a
   commenter asked whether scoping works "on repo level."
   [news.ycombinator.com/item?id=49698184](https://news.ycombinator.com/item?id=49698184),
   2026-09-14. **So what:** the skill-library UX needs scoped delivery by
   default, a craft note for the engineer agent, not a pricing question.

- Microsoft's Agent Framework team published "From Specialist Agents to
  Distributed Skills over MCP," arguing skills beat nested specialist
  agents for efficiency (3 model calls vs 6-7).
  [devblogs.microsoft.com](https://devblogs.microsoft.com/agent-framework/from-specialist-agents-to-distributed-skills-over-mcp/),
  2026-09-16. Third-party validation that skills-as-a-unit is the right
  industry direction.
- Two new skill-marketplace launches on HN in one week (skillbay.sh
  2026-09-17, Skillzero 2026-09-14) show the category is actively
  forming right now, not settled — a window to differentiate before a
  dominant paid player emerges.
- The Batch's 2026-09-11 issue drifted toward "how skilled AI engineers
  shape products," moving closer to alexandria's audience even though it

## The gap

The clearest unmet need this week: nobody attaches verifiable evidence to
a listed skill or automation. Every marketplace observed (skills.sh,
skillbay.sh, Smithery-hosted registries) lists skills as bare catalog
items with no confidence score, no citation, no trigger-reliability data
— and the market has just published dated, quantified proof that a large
share of those skills don't work as claimed. Alexandria's claim graph is
built for exactly this. See docs/market/opportunities-2026-09-18.md for
the full feature proposal ("skills with receipts").

## Ledger proposals

### 2026-09-18 — Skill-verification badge on every library entry
- Trigger: Show HN "State of Skills" report, 69% of public Claude Code
  skills don't reliably trigger
  ([news.ycombinator.com/item?id=49744398](https://news.ycombinator.com/item?id=49744398),
  2026-09-17)
- What: every skill in the paid library ships with a visible "verified
  against N sources, confidence X" line pulled from the claim graph, plus
  a trigger-reliability score, so the differentiator from every other
  skill marketplace is checkable, not asserted
- First step: define the badge schema against the existing claim-graph
  `supports`/`contradicts` edges and prompts/skill-extract.md
- Cost: $0
- Status: proposed

### 2026-09-18 — Scoped skill delivery by default
- Trigger: Show HN "Skillzero," skill libraries bloat context across
  unrelated tasks
  ([news.ycombinator.com/item?id=49698184](https://news.ycombinator.com/item?id=49698184),
  2026-09-14)
- What: the skill-library UX loads only skills relevant to the current
  task or repo by default, not the full library into context, answering
  the "does scoping work on repo level" question HN raised
- First step: define scoping rule (task/repo signal) with the engineer
  agent before the skill library ships
- Cost: $0
- Status: proposed

### 2026-09-18 — Orchestration-pattern benchmark, tied to the claim graph
- Trigger: Ask HN thread, practitioners explicitly asking for multi-agent
  observability/benchmark tooling and finding nothing
  ([news.ycombinator.com/item?id=49689454](https://news.ycombinator.com/item?id=49689454),
  2026-09-13)
- What: a maintained, versioned table of orchestration/harness patterns
  with measured cost, latency, and error tradeoffs, each row backed by a
  claim-graph citation, exposed as part of the $20/month tier
- First step: scope as a claim-graph query/view before committing to new
  data collection
- Cost: $0
- Status: proposed

## Report for the owner

The biggest market fact this week: the Claude skills ecosystem is
forming fast and has a proven quality problem (69% of a 216-skill sample
won't reliably trigger), and nobody in that ecosystem attaches evidence
to a skill. That is alexandria's clearest opening, more than any pricing
signal. For the product, this argues for building the claim-graph
citation into the skill library early, as the headline differentiator,
not a later polish pass. On pricing, this week's evidence does not argue
for a change to $20/month, it sits correctly between the essay-newsletter
and research-tool clusters, but it does surface one thing only you can
weigh: HN's volunteered anchor for a single skill is $5, so the pitch has
to sell the whole operational layer, evidence and automations included,
never a skill in isolation, or the price will look high against that
anchor. Nothing else this week argues for a pricing or positioning call
beyond what you already made on 2026-09-17.

## Update — 2026-09-18, later Friday run

A second pass the same Friday (following the morning's landscape and
positioning build, PRs #3 and #6). This extends rather than replaces the
findings above; full detail in the same-dated entries in
docs/market/landscape.md and docs/market/positioning.md.

### Findings that matter

1. **The "skills need trust infrastructure" thesis now has independent
   confirmation from a different angle.** This morning's evidence was
   about triggering reliability and marketplace skepticism. This run
   found Bastionskill, a Show HN launch scanning skills for malicious
   code before install
   ([news.ycombinator.com/item?id=49753727](https://news.ycombinator.com/item?id=49753727),
   2026-09-18) — a second, independent founder building toward skill
   trust, from the safety angle rather than the citation angle. **So
   what:** the gap alexandria targets is attracting builders from
   multiple directions at once. Worth watching whether Bastionskill or a
   peer expands from code-safety scanning into claim-verification, which
   would be a more direct future competitor than anything on the map
   today.

2. **Context bloat from unscoped skills is a lived production problem,
   not just a hypothetical.** Cloudflare shipped a real security-audit
   skill and its HN thread (205 points) is dominated by token-waste
   complaints ("I threw 1M tokens for nothing in a medium codebase") and
   a direct ask to scope skill loading ("consolidate all of your skills
   into a single skill and route everything thru that skill"), which a
   Cloudflare engineer confirmed is "being worked on."
   [news.ycombinator.com/item?id=49736466](https://news.ycombinator.com/item?id=49736466),
   2026-09-18. **So what:** this is the second, independent piece of
   evidence (after Skillzero this morning) for the "Scoped skill delivery
   by default" ledger proposal already filed — worth treating as
   corroborated rather than speculative when the engineer agent picks it
   up.

3. **Market-wide distrust of closed AI coding agents is running hot.**
   A 215-point HN thread this run covers a coding agent silently reading
   git history without disclosure; top comments demand open-source,
   auditable harnesses and argue trust has to be earned by disclosure,
   not asserted: "Either these people are honest and deserve your trust
   and business, or they don't."
   [news.ycombinator.com/item?id=49752422](https://news.ycombinator.com/item?id=49752422),
   2026-09-18. **So what:** this is evidence for a new proposal below —
   alexandria's own skills and automations should disclose what they
   read, write, and call, before install, not just what evidence backs
   their claims.

4. **A credible academic benchmark for agent memory exists; general
   orchestration-pattern benchmarking still does not.** Agent Memory
   Leaderboard (Tsinghua, Peking University, Oxford, and others; free,
   open, active) evaluates agent memory systems specifically.
   [agentmemoryleaderboard.ai](https://agentmemoryleaderboard.ai/).
   **So what:** refines, not reverses, this morning's finding — the
   orchestration-benchmark ledger proposal should consider citing
   existing credible benchmarks like this one in the claim graph as a
   first step, rather than assuming alexandria must build every
   evaluation from scratch.

5. **A secondary-source claim of a paid Anthropic Skills Marketplace
   (15% revenue share, launched 2026-05-01) could not be verified.**
   Multiple SEO-style blogs repeat this claim, but the primary sources —
   the `anthropics/skills` repo's marketplace.json and claude.com/blog/skills
   — describe only a free, open skills directory with no pricing
   mechanism. **So what:** not reported as fact. Flagged for a future
   pass to re-check, since a real paid first-party Anthropic marketplace
   would be the first same-tier internal comp in the skills ecosystem
   and would deserve its own positioning section if confirmed.

### Moves this week (addendum)

### The gap (unchanged, reinforced)

Still: nobody attaches verifiable evidence to a listed skill or
automation. This run adds a second axis to the same gap: nobody
discloses a skill's read/write/network behavior either. Both are trust
problems the market is visibly trying to solve piecemeal (one tool per
axis); alexandria's claim graph and the new disclosure proposal below
answer both from one system.

### Report for the owner (addendum)

Nothing this run argues for a pricing or positioning change beyond what
the morning brief already said. The one thing worth your attention: the
market is now solving skill trust as two separate problems (content
verification and behavior disclosure), and alexandria's claim graph
naturally covers the first but not yet the second. The new ledger
proposal is a cheap, $0 way to cover both from day one rather than
