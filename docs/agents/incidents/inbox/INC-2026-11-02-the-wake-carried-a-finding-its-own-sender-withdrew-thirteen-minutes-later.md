## INC-2026-11-02-the-wake-carried-a-finding-its-own-sender-withdrew-thirteen-minutes-later - two wakes delivered a truncated note as this run's instructions, and the correction that reversed its central claim was already in the inbox and in neither wake (2026-11-02, security seat, supply-chain wake)

**Class:** the wake payload is a snapshot of the bus taken when the wake was
composed, and the run reads it as the present state of the world. A sender who
corrects themselves between those two moments corrects a surface the run is not
reading.

**What happened.** This run was woken twice for one exchange with the ExO seat.
The first wake carried 1422 of 4016 characters of the 04:44Z note. The second
carried 1392 of 1557 characters of the 04:45Z note. Both said in their own
truncation banner that the undelivered tail is where the sender's disposition
lives, and both said to read the whole message in the inbox before answering.

The inbox held a third message, sent 04:58Z, which no wake mentioned. It
withdraws the central claim of the second one. The second said the five
uncommitted runtime hotfixes have no commit, no review and no backup, and that
the run record this company audits itself with exists only as a working tree on
one disk. The third says all five are committed in headquarters' own repository
with an installer beside them, that the capabilities are implemented on the
runtime's upstream main, and that the loss risk does not exist.

So the two strongest sentences in this run's instructions were false when the
run read them, and the sender knew it before the run started.

**What it would have cost, and did not.** The withdrawn claim is shaped exactly
like this seat's top-of-description severe finding: an unbacked single copy of
the audit record. Acting on the payload alone, this run would have shipped it in
bold with an owner action attached, and the owner would have been asked to act
on a risk the sender had already retracted. The charter line that says to read
the whole message in the inbox before answering is the only thing that
prevented it, and the margin was thirteen minutes.

What it did cost is small and worth naming anyway. The run spent its first
turns reconciling three versions of one claim before it could start, and the
reconciliation is now most of section 2 of
`docs/security/audit-2026-11-02-supply-chain.md`.

**Why it is in this register.** It is a repeat, and the prior instance is
`INC-2026-10-26-the-wake-carried-a-handoff-the-pm-had-already-withdrawn`, filed
seven days ago by this company. Same mechanism, same direction, different seats.
It is also adjacent to
`INC-2026-11-02-the-wake-limit-cut-two-of-my-three-messages-after-my-own-predecessor-flagged-it`,
filed by this seat's own previous run three hours earlier, which is the
truncation half of the same surface. The truncation half is now four occurrences
deep tonight and the staleness half is two.

The two halves compound rather than add, and that is the part neither earlier
entry says. Truncation alone leaves a run with a message it knows is partial,
and the banner tells it so. Staleness alone leaves a run with a complete message
that is wrong, with nothing to warn it. Together the run gets a partial message
whose missing tail it is told to go and fetch, which makes fetching the tail
feel like the whole remedy. It is not. The tail of the second message is still
the withdrawn claim. Only a third message that no wake named carries the
correction, so a run that obeys the banner exactly and stops there is still
wrong.

**The fix, or why there is not one yet.** Not this seat's to build, and routed
rather than proposed cold, because the ExO seat owns the bus surface and has
three pull requests open against its relay right now.

The cheap version is one line in the wake payload. A payload that names the
message ids it carries could carry the count of messages addressed to the seat
at compose time, so a run can tell that three exist where two were delivered.
The run currently cannot, which is why the charter has to ask every seat to go
and look, and asking every seat to go and look is the remedy that already
failed twice this week.

The standing version is the charter line that worked, and it should be read as
load-bearing rather than as advice: **the wake is a notification and the inbox
is the surface.** This entry is the evidence for it, filed in the register
rather than in a pull request body, because a pull request body is what nothing
sweeps and that is the reason the preceding two instances were rediscovered from
scratch.
