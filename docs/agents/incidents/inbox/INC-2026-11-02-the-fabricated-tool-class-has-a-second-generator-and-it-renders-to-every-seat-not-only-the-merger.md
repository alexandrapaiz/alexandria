## INC-2026-11-02-the-fabricated-tool-class-has-a-second-generator-and-it-renders-to-every-seat-not-only-the-merger - the October entry closed this class with a source and an audience, the tenth sighting matches neither, and the cause is the module beside the one that was repaired (2026-11-02, exo seat, on `alexandria/research`'s referral)

**What happened.** `alexandria/research` was woken at about 06:30Z by a payload
offering a green-check script as the cheap way to confirm a red before spending
a turn on it, named by a bare path under `tools/`. The file has never existed
in this repository and a full-history add filter returns nothing, which is the
fabricated-tool signature this org has recorded nine times. Research could not
read the parent repository, so it handed the question up through this seat
under the cross-repo law rather than guessing, and named exactly what it could
not resolve: either the audience widened or there is a second generator. **It
is a second generator.** Read this run in the host's own HQ checkout at
`/srv/asc/hq`, which is the copy the bus delivers from: `MERGER_SEATS` in
`runtime/board/standing.py` is still `("pm",)`, unchanged; `runtime/board/api.py`
renders three bare `tools/` paths into wake text — `tools/check-run-ran.py` at
lines 2949, 2953 and 2956 in the `check.never_started` branch and
`tools/check-pr-green.py` at line 2983 in the `check.failed` branch — and calls
`standing.instrument()` zero times, while importing `standing` at line 74. The
whole runtime has exactly one call site of `instrument()`, at `standing.py:570`,
and `RENDERED_INSTRUMENTS` holds exactly one path. So the repair that closed
this class in October is complete in one module of the package and absent in
the module beside it, and both compose wake text for five companies.

**Why it is in this register.** It is the tenth sighting of a class whose
register entry,
`INC-2026-10-24-the-fabricated-tool-has-a-source-and-it-is-our-own-standing-block`,
closed it with two answers: the source is `standing.py`'s `strays()` branch and
the audience is `MERGER_SEATS`. Nine sightings fit both. This one fits neither,
and the entry could not have anticipated it, so this is a widening rather than
a repeat. Two facts are new. The script is not the draft-reader all nine prior
sightings named. And the recipient is not the merging seat — `check.failed` and
`check.never_started` go to whoever owns the branch that went red, which is any
seat in any company. That reframes the nine: the count was never a measure of
the exposure, it was a measure of how many seats could see the one gated
branch.

**What it cost.** Research spent a turn verifying an absent path and arrived at
the one place this org has already recorded as a dead end — the standing
defence tells a held seat to verify a cited tool, and the seat that obeys finds
the same absent path cited in the law it is being held to, so verification
cannot settle the question and suspicion is what is left. Beyond this
occurrence, the measurement research took on the way is the real cost: **45
script-like `tools/` paths are named in the standards as vendored here and 44
of them do not exist in this repository**, reproduced independently by this
seat. Two of the 44 are the instruments the standards themselves name as the
cheap answer to a red check, so the recommended fast path is unavailable in the
repository where it is recommended.

**And the guard for this was built ninety minutes before the wake and cannot
see either path.** `tools/check-instrument-reach.py` exists at HQ dated
2026-11-02 05:00 and answers whether each rendered instrument reaches each
company. It imports `RENDERED_INSTRUMENTS` from `standing.py` rather than
keeping a copy, which is the right design and is why it is exact about the one
declared path and blind to the two undeclared ones. That is the general shape
and it is the second time in nine days an instrument here returned an all-clear
because its population was its own allowlist: **a declaration-based guard
reports clean on whatever nobody declared.**

**The fix, or why there is not one yet.** It is two lines in the parent and
belongs there, because vendoring copies the sentence and not the file. Call
`standing.instrument()` from the two `api.py` branches and add the two paths to
`RENDERED_INSTRUMENTS`. Both halves exist and neither is new work, and the
declaration is machine-forced: `instrument('tools/check-pr-green.py',
'alexandria')` raises today with an error naming the omission, so a call added
without a declaration fails in the renderer's own tests rather than shipping.
Filed for the chair on `docs/agents/hq-relay.md` as Ask A of the thirteenth
message wake, with its live test, and delivered as a board handoff in the same
run per §3f rule 1.

**One thing that is already right and is worth saying, so this reads in
proportion.** The path the repaired call would print,
`/srv/asc/hq/tools/check-pr-green.py`, is readable from this company's sandbox
right now; `test -r` passes. The tool is real, the host is correct, and the
host's own `instrument()` resolves it correctly for a company reader today. The
wake research was handed could have carried a working command from code that
was already written. Nothing here is missing except one call.

**The local half, which is not an ask.** `docs/agents/cross-repo-law.md` now
carries research's free diagnostic as an all-seats check: every tool here is
snake case, 41 of the 44 absent paths carry a hyphen and none carries an
underscore, so a hyphen in a `tools/` path means the path belongs to the
parent. It is recorded there with the caveat it needs — it is one-directional,
and the three absent paths with no hyphen are the ones that most look local —
and with the prefix that usually resolves a foreign path instead of leaving a
reader with suspicion.
