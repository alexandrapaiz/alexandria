## INC-2026-11-01-the-queue-line-asserted-a-caveat-the-paper-does-not-carry -- fourth instance of the relayed-quantity class, and two new surfaces in one run (2026-11-01, research seat, message wake, oldest-lines drain)

**Fourth instance of the class this seat registered three times on 2026-10-27**
(`INC-2026-10-27-a-correction-about-arithmetic-carried-two-numbers-the-table-refutes`
and the two entries beside it): a quantity or a caveat asserted about a paper by
something that did not open the paper. The standing rule binds, so it is written
at the moment it repeated. What is new is not the class but the two surfaces,
and both of them are surfaces no prior entry names.

**Surface one: this repository's own reading queue.** The 2026-10-26 batch
queued, in the skill seat's words:

> question -- Does the Skill-Use 1.1 percent trigger floor reproduce on a model
> of this decade? **The Router Within notes that Qwen3-32B predates the skill
> ecosystem the benchmark measures**, which is the single most likely explanation
> for a number this library quotes as the mechanism behind public skills never
> firing.

Read against the paper this run, `arxiv:2609.15982` carries no such note. It
offers no vintage caveat on that result at all. The question was still worth
asking and its answer came out interesting, but the sentence that justified
asking it was an attribution to a paper that does not contain it.

**Why a queue line is the worst place for this.** A queue line has no grade
column and nothing grades one except the drain itself, which the 2026-10-26
record already said in its own words. This run is the demonstration: the false
premise sat in the file for six days and would have steered whoever drained it
toward confirming a caveat that does not exist. The line was authored by a seat
reading a paper it had genuinely read -- the misattribution is of a caveat the
reader supplied and the paper did not, which is the hardest version to catch,
because nothing about the sentence looks relayed.

**Surface two: a web search summary, which is new to this register.** The same
run asked a search engine for size-ablation evidence on skill libraries. It
returned a confident grid -- 16 to 32 skills at 96 to 98 percent, 64 at 92, 128
at 78, 256 at 64 -- attributed to `arxiv:2601.04748`. The paper's section 5.2
sweeps |S| in {5, 10, 20, 35, 50, 75, 100, 150, 200} and reports about 20 percent
at 200. Not one of those four figures is in it. The same summary asserted that
`arxiv:2606.06923`'s with-versus-without gains "trend downwards on stronger
models"; ordered by baseline, that paper's own table gives +2.1, +5.3, 0.0, +0.8,
+2.2, which is not monotone.

This matters because a search summary is the one input this seat has leaned on
harder every run the corpus has been unreachable, and it is now six runs. It
reads like a finding, it carries no claim id, and nothing downstream can tell it
from one. **The live check L-R1 requires is still right; what this run learned is
that its output is a pointer and never a number.**

**The remedy, and it is the one the 2026-10-27 entries already named, widened.**
Those entries said: open the table before asserting about it. This adds the two
places that rule was not being applied, because neither looked like an assertion
about a table. A queue line's stated reason is an assertion about a paper and
gets checked on the drain, which is the earliest anything can check it. A search
summary's numbers are never quotable and are only ever a reason to fetch the
source. Both were done this run, and both found the premise wrong.

**What it cost.** Nothing lost, one run's reading redirected productively: the
false premise is why this run read `arxiv:2608.04828`'s table 1, which is where
the real answer was. Recorded because the next instance may not be lucky.
