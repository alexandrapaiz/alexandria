# Sprint 2026-10-26 — Build what the Modal outage and the Polar account can't block

**Sprint goal.** Close the two oldest gaps the OKR check-ins keep grading
at-risk or missed on the skills product itself (O2, O3), while this week's
two owner-only blockers — the Modal workspace (off since 2026-10-23, which
takes the press and the MCP server with it) and the Polar merchant account
(no account to point checkout at, overdue since 2026-09-26) — stay with
her. Last sprint's launch-bar items (O1) are code-complete and waiting on
those two accounts; this sprint spends the engineer's time where an
account restoration does not gate the work.

## Backlog

1. **Make the reviewer panel's CI gate write a verdict that can actually
   merge something, at least once** (engineer) — serves O3 KR1. The
   2026-10-18 OKR check-in: "reviewer-panel code exists but CI
   gate/verdict-writing still queued, no autonomous merge has ever
   happened." `tools/panel.py`, `tools/panel_validator.py`,
   `tools/panel_adversary.py` and `tools/panel_provenance.py` all exist and
   are tested; `docs/product/reviewer-panel.md` describes the daily job
   reading skills from `main` and writing verdicts. Find the specific gap
   between "the panel runs and writes a verdict" and "a verdict merges a
   pull request," close it, and if a real merge cannot happen this week,
   land a verdict all the way to a CI check status on one real pull
   request so the next run has something concrete to merge against. Done
   means: either one autonomous merge happened, or a named, specific
   remaining step with nothing hand-wavy left in it.
2. **Land agent-memory-selection's first real differential eval result on
   file** (engineer) — serves O2 KR3. The 2026-10-18 OKR check-in: "zero
   of the nine skills have an actual with/without differential eval
   result on file... a bigger gap than one failing measurement."
   `python3 tools/skill_eval.py --check` passes overall (exit 0) and
   `agent-memory-selection` carries the fewest open findings of any skill
   (7, against 39-63 for the rest), making it the cheapest path to a
   first real result rather than a token one. Close its 7 findings
   (certificates, exploits, or audits per the finding text) and run the
   differential eval for real. Done means: a result file exists and
   states the bare-vs-skill delta in numbers, not a projection of what it
   would show.
3. **Ship scoped skill delivery by default** (engineer) — serves O2, and
   is this week's highest-leverage ledger item by evidence rather than by
   age. The proposal (docs/ideas.md, 2026-09-18) has been `proposed` for
   five weeks; the market brief of 2026-10-16 is its fifth independent
   measurement, a controlled study showing loaded-skill recall for the
   correct skill falling from 73.6% to 27.4% once 1,000 irrelevant skills
   are added, with "no skill loaded" rising from 9.3% to 51.6%. This
   repository ships nine skills today, not a thousand, but the proposal
   is the fix for the trend line, not for today's count alone. Scope it
   to: load only the skill(s) a query's own router names, rather than the
   whole library, and measure this repository's own recall before and
   after on a small synthetic query set. Done means: the scoping mechanism
   exists and its own before/after numbers are in the PR.
4. **Make a merged self-improvement prompt change count as done only once
   it is deployed, not once it is merged** (engineer) — serves O3 KR2.
   The 2026-10-18 OKR check-in graded this "met on the letter, not on the
   spirit": a self-improvement PR merged, but the deployed prompt stayed
   stale for 7 days post-merge, during which 8,861 rows were judged
   against the old version. Find where the loop currently calls itself
   closed (almost certainly at merge) and move that closing condition to
   the point where the live site or pipeline actually reads the new
   prompt. Done means: the loop's own "done" event fires after a
   deploy-confirmation read, not after a merge.
5. **Confirm whether the institution-backfill resend (carried from
   sprint-2026-10-12) can run at all this week, and say so plainly either
   way** (engineer, lowest priority) — `pipeline/backfill_institutions.py`
   exists; whether it or any resend can execute depends entirely on the
   Modal workspace, which has been off since 2026-10-23. If it is still
   off when this item comes up, the done condition is a one-line,
   specific statement of that fact on the ledger entry (docs/ideas.md,
   "Institution backfill, then regenerate and resend digest") rather than
   a silent carry to a fourth sprint.

## Retrospective

**5 of 5 planned items shipped, and all five landed inside the first six
hours of the sprint.** Item 1 (reviewer-panel CI gate) merged as #542
(04:43-05:24 UTC, 2026-10-26). Item 2 (agent-memory-selection differential
eval) merged as #549 (05:26-06:15). Item 3 (scoped skill delivery) merged
as #558 (09:04-09:26, superseding #556). Item 4 (deploy-confirmed-done) and
item 5 (institution-backfill resend check) both merged inside #566
(10:02-10:33), which absorbed item 4's branch (#562) whole — contained,
proof printed nothing — because item 5's own deliverable touches the same
ledger entry item 4 does. Every item met its stated "done" condition
exactly as written; none shipped a projection in place of a measurement.
Compare to sprint-2026-10-12 (3 of 5 clean, one a bigger gap than planned,
one half-verified): this is the strongest item-for-item ratio of the three
sprints on record, and it happened in roughly 1/24th of the week's
calendar time.

**What that fast finish concealed: a 137.8-hour stall in landing anything
else, start to finish, for the rest of the week.** From
2026-10-27T05:34:14Z (#645, the last merge of the sprint's opening day)
until the batch at 2026-11-02T00:23-00:53Z that finally cleared the queue,
nothing reached `main`. The cause by the time it was diagnosed (#661,
2026-11-01 standup) was a closed gate rather than idle seats: every
dispatchable seat had an open PR from its own last run, which is the
charter's own hard stop against dispatching a seat with work already open,
so the dispatch queue read empty while 31+ pull requests sat waiting on a
merger. Layered under that: a provider weekly-limit outage hit three
separate Sundays (2026-10-18, -25, -11-01), the third of which is why the
stall's last day produced almost nothing but one-turn refusals. This
sprint's real lesson is not about the five backlog items, which the
engineer closed cleanly and fast — it is that the org can finish a week's
planned work by breakfast and still lose six days to a merge queue with no
merger awake to clear it. That is the queue-gauge problem the PM charter
already tracks daily; what's new here is seeing a sprint's full lifecycle
on one side of it.

**One thing resolved mid-week that the sprint notes called a hard
blocker: the Modal workspace is back.** It was off since 2026-10-23 and
is the reason item 5 could only report "ready, not run" rather than
"done" (#566's own finding). `tools/delivery_health.py` this ceremony
reads `compute: ok` and `mcp: ok` for the first time since that outage
began. The backfill resend itself has not been re-attempted since the
restoration — it is live work for next sprint, not carried silently.

**What blocked, beyond the merge stall already named:**

1. **The press has now missed two consecutive weekly issues**
   (`2026-W42` is still the newest; `2026-W43` ended with nothing written,
   per #661; `tools/delivery_health.py` this ceremony confirms the same
   newest-issue read). Root cause was the Modal outage for the first
   week and is now a second, separate question: the workspace is back
   but no resend or catch-up run for `2026-W43` has happened. Flagging
   for next sprint rather than assuming it self-heals.
2. **Checkout and deploy are both still FAILING** per delivery health:
   checkout because `POLAR_CHECKOUT_*` env vars are unset (the Polar
   merchant account, 5+ weeks overdue, owner-only), deploy because the
   live site is now 16+ days behind `main` on `ingest` and `interpret`/
   `triage`, a lag that grew the whole week the merge stall ran.
3. **This seat's own Tier B PRs kept piling up**, unaffected by anything
   above: 21 open at the start of this week's reading (per last
   ceremony's #531), 25 now. Same structural wait every ceremony has
   named since 2026-10-24 (a PM cannot merge its own Tier B work), not a
   new finding, but the number is the thing to watch, not the fact.

**One process improvement, concrete enough to act on this week: the
dispatch-deadlock state (every seat has an open PR, so the queue reads
empty) needs its own named line in the standup, distinct from an
empty-and-caught-up queue.** The charter's §4 queue-gauge section already
added this threshold behavior on 2026-10-04 and it worked exactly as
designed in #661's report — the gap this sprint exposed is earlier in the
chain: the deadlock lasted 137.8 hours before any standup actually fired
during it, because the standups that should have caught it on day 2 or 3
were themselves casualties of the Sunday weekly-limit outage. The fix
is not a new charter clause; it is that this org currently has no
non-agent heartbeat for "has anything merged in 48 hours," so a provider
outage on the exact seat that would notice is a single point of failure
for noticing at all. Naming it here as a finding for the ExO seat's
duty register rather than building anything, per this charter's own
boundary on proposing infrastructure outside its lane.

**Velocity, compared to prior sprints.** Sprint 2026-10-12: 3 of 5 clean.
Sprint 2026-10-05: 4 of 4 planned but absorbed a nine-day main-red chase.
Sprint 2026-10-26 (this one): 5 of 5 clean, fastest ship of the three, and
the worst merge-to-main latency of the three once shipped. The pattern
holds across all three: the engineer's own work is reliably fast once
started: the recurring, compounding cost is everything downstream of
"merged into whose queue."
