### What it needs, named precisely rather than "fix the test"

`tests/test_corpus_drain.py::test_every_paced_caller_tells_pace_how_big_its_call_was`
does a literal substring check: every path in `budget.PACED_CALLERS` must
contain the text `cap.last_tokens` somewhere in its source, because that is
this repository's convention for "paces from a provider-counted call size,"
checked textually rather than by running a call. `tools/skill_eval.py`'s
`Subject.pace()` genuinely reads a provider-counted size — `Subject.ask()`
sets `self.last_tokens = getattr(self.cap, "last_tokens", 0) or 0`
immediately after every real call, copying `Cap.last_tokens` (the field
`pipeline/llm.py`'s `Cap.record()` sets from the provider's own `usage`
block) into a field scoped to this one `Subject` instance. That per-instance
copy is deliberate and correct, not the defect: the PR's own comment on
`pace()` explains why a subject and a judge that share one `Cap` must not
read `self.cap.last_tokens` directly at pace time, since that field is
overwritten by whichever of the two last called and a judge-sized pause on
a subject call is the same single-limit mistake the PR is fixing one layer
up. The defect is narrower: the copy is spelled
`getattr(self.cap, "last_tokens", 0) or 0`, which never renders the
contiguous text `cap.last_tokens`, so the cross-file check cannot see it.

**Verified fix, one line, `tools/skill_eval.py:2137`:**

```python
self.last_tokens = self.cap.last_tokens if hasattr(self.cap, "last_tokens") else 0
```

The `hasattr` guard is load-bearing and must stay: `tests/test_skill_eval.py`
builds a `FakeCap` with no `last_tokens` attribute (around line 1601) to
exercise `Subject.ask()` without the real `Cap`, and a bare
`self.cap.last_tokens` raises `AttributeError` against it. Applied this one
line in a throwaway worktree (not committed, not pushed — product code is
outside this seat's writable surface) and reran:
`python3 -m pytest tests/test_corpus_drain.py::test_every_paced_caller_tells_pace_how_big_its_call_was tests/test_skill_eval.py -q`
→ **138 passed**, including the previously-failing assertion and every
`FakeCap`-based test. This is the only change needed; nothing else in the
diff's logic, tests, or ledger entries is in question.
