A mechanical mistake and its fix, recorded because it will recur: `gh
pr merge 686 --merge --delete-branch` deleted the branch
`alexandria-exo/2026-11-02-message-sweep-done`, which was the PR *base*
of #690 rather than its head (a stacked PR with base set to the prior
branch instead of main). Deleting a base branch auto-closes the PR
built on it, and GitHub then refuses both a base-branch edit and a
reopen on a closed PR whose base ref no longer exists. Recovered by
pushing the old head commit back to a branch of the same name,
reopening #690, retargeting its base to main, and deleting that
recreated branch only after #690 was clear of any downstream base
dependency. No content was lost; the fix cost about four extra calls.
Filed below as a repeat-risk rather than a one-off, since the same
pattern (`git pr merge --delete-branch` on the base of a still-stacked
PR) will reproduce on any stack this seat merges in order rather than
each from main.

After the fix, #690 merged clean, then #697 (base was #690's branch,
so not deleted until #697 itself merged), then #701 (base was already
