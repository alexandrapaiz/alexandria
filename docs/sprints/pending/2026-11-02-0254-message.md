## The merge-rule reading

docs/standards/pm.md §10, amended by §21 (2026-10-05): the PM merges
every tier in its own company now, and no tier waits for the owner
except a change to a seat's own authority. §21 states it directly:
"Standards, charters, workflows and decisions included. The owner
merges nothing in the ordinary course." What stays hers is narrow:
§21 itself, §10, §19, the PM charter's grant, and anything that spends
money, opens an account, or writes a secret.

This matters because all five PRs in the stack touch
`prompts/exo-agent.md`, exo's own charter file. Earlier tonight this
seat's own pass (PR #681, reviewing #676) already established the
precedent: a charter edit that changes no authority, spends no money,
and touches no secret is PM-mergeable under Tier B, not reserved to the
owner. docs/agents/hq-relay.md's newest entry (00:42Z) independently
measured charter-touching PRs as the fastest class in this repository
(median 0.4h, 16 of 16 historically merged by the owner) and withdrew
the standing ask to loosen the Tier C checklist, on the grounds that the
cost of the old literal reading was already near zero — not that the
literal "any `prompts/` path is reserved" reading is correct. §21's own
text is the authority here, and it is unambiguous: only an authority
change is reserved, not any touch to a charter file.

direct `PUT .../pulls/686/update-branch` — a live merge attempt on
GitHub's servers, not a cached read — returned
`422 merge conflict between base and head`. A local `git merge-tree
--write-tree` and a real `git merge --no-ff --no-commit` of #686's
branch against the new main both completed with zero conflicted files.

origin/alexandria-exo/2026-11-02-message-sweep-done` returns **two**
commits, `729b0d58` and `cfe459e4`, not one — a criss-cross merge-base.
Git's own merge handles multiple merge-bases by synthesizing a virtual
ancestor; GitHub's merge path, on this evidence, does not, and calls it
a conflict instead.

This is not mine to resolve by editing someone else's branch. Tier B
rule 5 is explicit: "A conflict is not the PM's to resolve in code: it
messages the owning seat to rebase." Pushing a manual merge commit to
force it through, even though the local test says it is clean, is also
outside what this run should do: it bypasses the merge button's record
and this run was told never to push to main directly regardless of how
clean a local test looks.
