## Backlog

1. **Panel verdict schema and the provenance reviewer** (engineer) — Add a
   reviewer-verdict table to `db/schema.sql` (one row per promotion per
   reviewer, reviewer constrained to `provenance`, `adversary`,
   `validator`, verdict constrained to `pass` or `fail`, evidence as
   jsonb, created_at) plus a view that reports whether a promotion has a
   unanimous pass. The statement must stay idempotent so
   `modal run pipeline/db_setup.py::apply_schema` can be re-run. Then
   implement the provenance reviewer as a plain function in `pipeline/`:
   given a skill's markdown and its cited claim ids, it checks that every
   cited id exists in `claims` and that the cited claim supports the
   sentence citing it, and it returns a verdict row. Done means the
   function runs locally against `skills/harness-engineering/SKILL.md`
   (twelve claim ids in its frontmatter) and the PR shows its output, one
   deliberately wrong claim id produces a `fail` with the id named in the
   evidence, and the schema applies cleanly. Do not wire it into the
   weekly cron yet and do not merge anything.
2. **Skill-extract prompt** (engineer) — Write `prompts/skill-extract.md`,
   the prompt that turns a cluster of mutually supporting claims into a
   draft skill in the format `prompts/weekly-agent.md` defines (name, when
   to use, claims it rests on, procedure, tradeoffs and failure modes).
   Draft it against one real cluster found through `semantic_search` or a
   `supports`-edge query. Done means the PR attaches the cluster's claim
   ids and the draft skill the prompt produced as evidence. The draft is
   evidence only. Nothing is written into `skills/`, because promotion
   belongs to the panel.
3. **Institution backfill, then regenerate and resend the digest**
   (engineer) — Run the institution backfill (the owner's scratchpad
   script `backfill_institutions.py`, brought into `pipeline/` if it is
   not already there) inside the daily Groq budget, then regenerate the
   current week's digest and resend it through the existing
   `send_newsletter` path. Done means the PR reports the count of papers
   with null institutions before and after, the regenerated digest row's
   week, and the send result. If the session has no Modal or database
   credentials, report that and stop instead of working around it.
4. **Provenance reviewer runs inside the weekly cron** (engineer, stretch,
   depends on item 1) — The weekly run lists open promotion PRs, runs the
   provenance reviewer over each, and records one verdict row per PR. No
   merging: the merge step waits on the adversary, the validator, and the
   PR-merge token scope the owner has to mint. Done means a dry run over
   the current open promotion PRs (or a fixture if there are none) writes
   verdict rows and the PR description shows them.
