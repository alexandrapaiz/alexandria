**One process improvement.** The ceremony itself skipped a week
(2026-10-19) with nothing in any charter saying what should happen when it
does. The standup ran that day and every day; it is not built to open a
sprint or close one, by its own design ("a standup that grows into a
ceremony has failed at being daily"), so the gap sat unflagged until this
run found it by noticing no `sprint-2026-10-19.md` existed. Concrete fix,
proposed in the ledger rather than built here since it would touch
`prompts/pm-agent.md`: the standup's own output should name, every day,
whether the current sprint file's end date has passed with no successor
opened, the same way it already names a stale pending-tracker line. A
missing ceremony should be as visible as a missed merge.
