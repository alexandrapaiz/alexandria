## Backlog

1. **Remove the digest teaser gate; issue pages render full content**
   (engineer) — The digest is free in full per vision.md §0 (amended
   2026-09-17). Remove any first-paragraph-public-rest-locked logic from
   issue pages and the entitlement check that gates it. Done means an
   issue page renders its complete content to a signed-out visitor, and
   no code path still checks a subscription tier before showing digest
   content. If the site has no digest content wired to real rows yet,
   note that gap in the PR rather than building a data pipeline as a side
   quest; that is item 3.
2. **Gate the skill library, claim graph, and automations behind the $20
   spine instead** (engineer, depends on item 1) — Move the entitlement
   check item 1 removed from digest pages onto the library, graph, and
   automations routes: signed-in email checked server-side against
   `subscribers` where status is active and tier is the $20 spine. Done
   means a signed-out or non-entitled visitor sees a locked state on
   those routes only, the digest routes are unaffected, and the pricing
   page copy names one free tier (the digest) and one $20 tier (the
   spine), not the old $10/$30 split.
3. **Real digest content on the site's archive, not an empty page**
   (engineer) — The market walkthrough found "Read an issue" renders
   empty. Wire the archive and issue routes to the digests table (or, if
   no session has database credentials, to one real digest fixture
   checked into the site so the page is never empty). Done means visiting
   the archive as a signed-out visitor shows at least one complete,
   readable issue end to end.
4. **Email capture on home and pricing, before Stripe exists** (engineer)
   — market proposal, 2026-09-18. Both CTAs currently dead-end at
   "Coming soon" with no way to leave an email. Add a one-field signup
   writing to the existing Neon `subscribers` table with status
   `waitlist`. Done means a submission on either page inserts a row, a
   duplicate email does not error the page, and the user sees a
   confirmation state.
5. **Make the hero metric live** (engineer) — market proposal, 2026-09-18.
   `site/app/page.jsx` hardcodes "3,431 papers ingested this week." Query
   the real weekly ingest count at build or revalidate time, matching the
   revalidate pattern already used on the desk page, with an honest
   fallback string if the query fails. Done means no hardcoded ingest
   number remains in source.
