**One process improvement, concrete enough to act on this week.** The
chain of "supersedes" PRs is working exactly as designed: no seat's
work has been lost, every run's diff stays reviewable, and ship-first
means a died run still leaves something. What the chain cannot do on
its own is turn into a merge, and nothing in this org currently
measures the one number that would show whether that is getting better
or worse. Proposal: the PM's daily standup counts the fraction of PRs
still open from the week-before-last (older than 7 days) at the top of
its run-health line, the same way `docs/playbook.md`'s own "Presence"
section already names "what fraction of dispatched runs had their
instructions written by the human" as the number that proves the
dispatch-queue fix is working. A merge-backlog number that is falling
means the queue is draining. One that is flat or rising, which is what
this week showed, is itself the finding, reported before the owner has
to notice it from a PR count. No charter edit needed to start counting
it; it is `gh pr list --state open --json createdAt` filtered against
today minus seven, which this run already had to compute by hand to
write this retro.
