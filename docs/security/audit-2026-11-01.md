## The severe findings, first

### 1. One leading space in `DATABASE_URL` hands the database password to an MCP caller (found, measured, and fixed here)

`db()` in `mcp/server.py` passed `os.environ["DATABASE_URL"]` straight to
`psycopg.connect`. libpq treats a string as a URI only when it begins exactly
with `postgres://` or `postgresql://`. Anything else is parsed as a
keyword/value connection string, and the first error that parse raises is
`missing "=" after "<the whole value>"`. Every exception out of `db()` leaves
through an MCP tool call to whoever made it.

Measured against `psycopg[binary]==3.2.4`, which is the version the image pins:

| the value of the secret | password reaches the caller |
| --- | --- |
| one leading space | yes |
| one leading tab | yes |
| stored with its surrounding quotes | yes |
| wrong scheme, `mysql://` | yes |
| no scheme at all | yes |
| one trailing space | no |
| one trailing newline | no |
| well-formed | no |

**This is the 2026-10-01 audit's finding, which that report filed as `low` and
two later sweeps carried at `low`.** The reasoning was that it "needs a
malformed `DATABASE_URL` to trigger, which means the server is already broken
when it happens, so it is a narrow path." The first half is right and the
conclusion does not follow. The malformation that leaks is leading whitespace
in a pasted secret, which is the most ordinary way a secret is malformed, and
the asymmetry with trailing whitespace is what makes it impossible to guess:
the operator who adds a trailing newline is fine and the one who adds a leading
space is not, and neither gets a warning. The caller who reads the message is
authenticated and is still not the owner.

Three sweeps carried this at `low` because each read the previous report rather
than the library. That is the same mistake the 2026-10-15 audit caught itself
making about the `digests/` withdrawal, and wrote down as the transferable
lesson: a severity justified by reasoning about a dependency needs re-running
against the dependency.

**Fixed here, in two parts, because the first closes the malformations we know
about and the second closes the class.** The secret is stripped before libpq
sees it, so the common paste error stops being an error at all. And every
connect failure is re-raised through a `_redact` that strikes out the DSN, the
raw environment value and the password alone. The exception class and any
message carrying no credential survive unchanged, so a caller debugging its own
integration still learns that a host did not resolve. `from None` is
load-bearing there: a chained original prints the unredacted message back out
through the traceback.

`tests/test_mcp_dsn_redaction.py` is the gate, nine assertions. `db()` lives
inside `serve()` and cannot be imported without Modal, a database and the
embedding model, so `_redact` is lifted out of the source with `ast` and
executed on its own. All five single-guard mutations were confirmed to turn it
red before it was kept.

**The one thing the owner has to do, and it is not a rotation.** `modal deploy`
bakes this repository into an image, so merging this changes nothing until the
MCP server is redeployed. That gap is this product's own recorded defect,
`INC-2026-10-12-meta-review-proposal-merged-never-deployed`, where a merged
proposal spent twelve days undeployed with 8,861 rows judged against the
superseded prompt. Until the redeploy, the live server still has the old
`db()`. In the meantime the cheap mitigation is independent of any deploy:
confirm the `neon` secret's value has no leading whitespace and no wrapping
quotes.

### Fixed here: the funnel published a database error message at a public URL

`/api/funnel` is public and unauthenticated on purpose, and the argument for
that is written at length in its own route file. It serves three fields that
all came from one function, `reasonFor` in `site/lib/path.js`: `counts_reason`,
`skills_reason` and `last_record_error`. For every Postgres code but 42P01 that
function returned `String(error.message).slice(0, 200)`, so a database failure
turned the endpoint into an internals channel.

**The rule it broke is this codebase's own, and it is written down one file
over.** `site/lib/delivery-core.js` states it beside `UNREADABLE_REASONS` in
these words: a closed vocabulary and never an error message, three strings this
codebase chose, "so a Neon error carrying the host and the role it failed to
authenticate cannot reach a public response through this field."
`site/lib/delivery.js` keeps it in its own catch with `error?.name` and nothing
else. `path.js` is the newer of the two files and went straight past it.

So the finding is not that somebody chose wrong, it is that **the rule was
recorded in a comment and enforced by nothing**, which is incident 20's shape
exactly: a correct ruling written in the right place by the right hand, and
violated by the next artifact because nothing between the ruling and the
artifact ever opened the file.

`reasonFor` now answers from a closed vocabulary. 42P01 keeps its sentence
naming the one command that closes it, 42703 gains one, and everything else is
`a query failed: <class>`. The distinction the file exists to protect survives
intact: a count that never arrived is still not a count of zero, because the
reason is still non-null and still names the remedy where there is one.
`tests/path.test.mjs` gains the gate, in the idiom that file already uses for
its privacy promise, and it was confirmed to fail against the
message-returning form before being kept.

### The MCP server

`mcp/oauth_flow.py` has not changed since the last sweep, and re-reading it
this run found nothing new. The properties that matter are all present: PKCE
with `S256` required and no other method accepted, HS256 with an explicit
`algorithms=["HS256"]` allow-list on decode so there is no algorithm
confusion, a `typ` claim checked against the expected type so an access token
and a refresh token cannot be swapped, `hmac.compare_digest` for both the
passphrase and the signature comparison, single-use codes through
`consumed_codes`, and a revocation check before claims are returned.

Token lifetimes are long and recorded rather than filed: `ACCESS_TTL` 24 hours,
`REFRESH_TTL` 180 days. For a single-user server reached through the owner's
throttled passphrase that is a deliberate convenience trade, and it is the
reason finding 2's blast radius is worth closing at the database role instead.

`sql_query` is finding 2 above. `db()` was finding 1 and is fixed.

**Rate limiting is unchanged from 2026-10-01.** The passphrase is throttled
through `auth_attempts`; the tools are not. An authenticated caller can run
`sql_query` as often as it likes, bounded by `statement_timeout = 15000` per
statement and Modal's scaling. For one user that stays a cost question.

## Method, so the next run can repeat or distrust it

The history scan is reproducible from this description and the script is not
committed, for the reason the 2026-10-01 report gives: a one-off script nothing
maintains is worse in the repository than out of it. Unshallow the clone and
widen the fetch refspec first, or every comparison below lies. Enumerate with
`git rev-list --objects --all`, filter to blobs with `git cat-file
--batch-check`, stream them through `git cat-file --batch` in batches of 500,
and match 20 credential patterns with a placeholder filter. Report the file,
the blob and the kind, and never the value.

Three things in this report were measured rather than reasoned, and all three
changed the answer a previous sweep had written down. The DSN leak's severity
came from running `psycopg.conninfo.conninfo_to_dict` against eight malformed
shapes, not from reading the 2026-10-01 note. The two red skill tests were
bisected by checking two commits out into worktrees and running the
assertions. The funnel's path normalisation was probed by executing
`path-core.js` against adversarial inputs including an address in a query
string.

**And one method note that is worth more than any of them, because it is a trap
this run fell into and caught.** Two of the new gates in
`tests/test_mcp_dsn_redaction.py` were first written as substring checks over
the source, and one of them passed on a `db()` whose guard had been deleted,
because the comment above the guard explains the words the test was searching
for. `tests/path.test.mjs` documents the mirror image of this and strips
comments to dodge it. Both gates read the parse tree now, where there are no
comments to be fooled by. **A source-text gate is confirmed by mutating the
source it guards and nothing else**, and the two that bit and the two that did
not were indistinguishable until that was done.

Ban list checked on this report.
