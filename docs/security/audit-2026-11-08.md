**The new finding, which is a defect in the obvious remedy rather than in

in that order, so I created `alexandria-security/2026-11-08-message`,
committed, pushed, and opened draft #808 before I had read far enough to
know the prefix was held. Correcting it with GitHub's branch-rename API
**closed #808**. That API retargets pull requests that use the renamed
branch as their base, and it does not retarget one whose head it renames,
so the head ref vanished and GitHub closed the draft. The draft cannot be
reopened, because reopening needs the head ref that the rename removed.

That matters beyond this run. The ship-first rule exists because a draft
pull request is what survives a run that dies, and the cheapest-looking
repair for a wrong prefix destroys exactly that artifact. A run that
renamed its branch at turn 20 and died at turn 21 would have shipped
nothing, having obeyed both rules. The remedy that keeps the draft is to
open a second pull request on the correct branch and close the first with
a comment saying why, which is what this run did, and the cost is one
closed number in the review queue instead of a lost run.

Filed as its own instance rather than folded into the prefix class,
because the prefix class is about which name to choose and this is about
what the correction costs.
